# UX-чек-лист для системы учёта заявок

## 1. Экран входа
- Есть поля для логина и пароля.
- Подписано, какие данные нужно вводить.
- Есть кнопка «Войти».
- При ошибке показано понятное сообщение, например: «Неверный логин или пароль».
- Пароль можно скрыть или показать.
- После успешного входа пользователь попадает на главный экран.

## 2. Список заявок
- Видно название страницы и основные пункты навигации.
- У каждой заявки отображаются номер, тема, категория, дата, статус и исполнитель.
- Есть поиск по номеру или теме заявки.
- Есть фильтры по статусу, категории и исполнителю.
- Понятно, какие фильтры включены; их можно сбросить.
- Статусы различаются не только цветом, но и текстом: «Новая», «В работе», «Выполнена», «Закрыта».
- Если заявок нет, отображается сообщение и, если у пользователя есть право, кнопка «Создать заявку».
- Ошибки загрузки списка объясняются понятным сообщением.

## 3. Создание заявки
- Есть поля для темы, описания и категории.
- Обязательные поля отмечены.
- Есть кнопки «Создать» и «Отмена».
- До отправки проверяются обязательные поля.
- Если данные введены неправильно, показано, что именно нужно исправить.
- После создания показывается подтверждение, а заявка появляется в списке.

## 4. Карточка заявки
- Видны номер, тема, описание, дата, категория, статус, заявитель и исполнитель.
- Комментарии показаны в понятном порядке; видно, кто и когда их оставил.
- Доступные действия зависят от роли.
- Перед удалением или другим опасным действием показывается подтверждение.
- После изменения данных пользователь видит сообщение об успешном сохранении.
- Если произошла ошибка, изменения не пропадают без предупреждения.

## 5. Общие требования
- Названия кнопок и пунктов меню понятны.
- На каждом экране ясно, куда перейти дальше.
- Интерфейс учитывает роли пользователей: заявителя, оператора, исполнителя и администратора.
- Цвета статусов различимы и не мешают читать текст.
- Формы и сообщения об ошибках понятны и не перегружены техническими терминами.
